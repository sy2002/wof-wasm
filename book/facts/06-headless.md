## What stands in for the machine

8. The operating system is answered by stubs, one Python method per library call, named after the library and the function; the program's call lands in a made-up library base whose every jump-table slot is an `rts`, but for `mathffp.library`'s, whose slots are `jmp` instructions into the ROM (`0x0CE000`); a code hook over the area of the fake bases stops the emulation, the method does the work and returns D0, and the program resumes. Source: `tools/headless_os.py`, docstring; `tools/headless.py`, `Headless.__init__` (the `rts` in every slot, the `_range_stop` hook), `_map_rom_mathffp` (the `jmp` table at `MATH_BASE`), `_os_call`, `leave`; `re/notes/headless.md`, "Memory map" (`0x0C0000`–`0x0C9FFF`; `0x0CE000` "its slots jump into the ROM, outside the hooked range"); review B13.
9. Why the emulation is stopped before a stub works: a register written inside a Unicorn hook is lost, because the translated block carries on with its own copy; memory written inside a hook is kept. The prose has it in the developer's sidebar. Source: `re/notes/headless.md`, "Unicorn, as it behaves here", first point; `tools/headless.py`, the comment above `_range_stop`.
10. The stubs answer 60 functions of the system, of four libraries (exec 26, dos 14, graphics 15, intuition 2), a device (console.device's `RawKeyConvert`, 1, behind the base input.device and console.device share) and a resource (`ciaa.resource`, 2); one of them, `RawKeyConvert`, runs the ROM's own routine (claim 19). They are 50 methods, ten of them answering a second function under its name: `OldOpenLibrary` by `OpenLibrary`'s, `Permit`, `Disable` and `Enable` by `Forbid`'s, `RemPort` by `AddPort`'s, `DisownBlitter`, `BltClear`, `BltTemplate` and `RectFill` by `OwnBlitter`'s, `Draw` by `Move`'s; `os_init` is no library call. "Sixty functions of the system" is exact; "sixty stubs" would not be. `mathffp.library`, one of the game's five library bases of chapter 4, has no stub: its slots lead into the ROM. Source: `tools/headless_os.py`, the `os_` names counted by grep, the aliases at its lines 124, 155, 176, 312, 313, 343; `tools/headless.py`, `LIB_NAMES` and its comment ("input.device and console.device share the one device base"), `DEVICE_FUNCTIONS`, `RESOURCE_FUNCTIONS`; `re/notes/headless.md`, "The stubs"; the controller's correction 6; review B7.
11. A call without a method ends the run with the library, the function and the call chain, so that nothing the game asks for is answered by accident. Source: `tools/headless_os.py`, docstring; `tools/headless.py`, `_os_call` (`'%s.%s is not stubbed; called from %s'`); `re/notes/headless.md`, "The stubs".

13. A directory is listed in the order the disk's file system hands its entries out, read from the disk image. Source: `re/notes/headless.md`, "Directories"; `tools/headless_os.py`, `adf_order`; `SPEC.md` 8, row "Whole game, logic".
14. Memory comes from a bump allocator that never reuses an address: each address depends only on the requests before it, which the game makes in the same order in every run, so every address is the same in every run, and fresh memory is zero; that matters because the state is compared address by address and holds pointers. ## Time: the program runs until it waits

32. The problem: the main program blocks in its waits and the VBlank interrupt is asynchronous; on the machine the interrupt arrives when the picture is done, wherever the program is (chapter 2; **(reference: HRM, chapter 7, interrupts)**). Unicorn imitates only the processor, so nothing in it finishes a picture; delivering interrupts after some count of instructions would make every result depend on how the emulator counts; and the port runs C, not these instructions, so a VBlank at an instruction count could never be reproduced on its side, while the waits exist on both sides and there the two agree VBlank for VBlank. Source: `re/notes/headless.md`, "Scheduling", first paragraph; `SPEC.md` 6.3 ("the headless original delivers a VBlank exactly where the program waits, and so the two agree VBlank for VBlank"); chapter 5 ("Unicorn, a library that imitates processors"; "the emulator imitates only the processor"); chapter 1 ("only the processor is emulated"); review C3.
33. The rule: the program runs until it waits, and VBlanks happen only where it waits; nothing else about time reaches the program. Source: `re/notes/headless.md`, "Scheduling" (in bold); `tools/headless.py`, docstring.
34. The wait points, five kinds; a wait point is a place where the program waits, for the next picture, for a time or for the music's fade to end, and where the harness therefore lets VBlanks happen: the spins in `wait_vblank` (the routine at `0x01AA3E`, its spin's test at `0x01AA44`) and `wait_next_vblank` (the routine at `0x01AA32`, its spin's test at `0x01AA36`; `re/functions.csv` `01aa32,wait_next_vblank`, `re/Wings.lst` `0x01AA32` `clr.b`, `0x01AA36` `tst.b`) reached with `vblank_flag` clear, one VBlank, which sets the flag; `graphics.WaitTOF`, one; `dos.Delay(n)`, n × `video_hz` / 50; the entry of `frame_update` (`0x010228`), the start of a pass, as many as are still owed so that the configured number lie between this pass's start and the previous one's, at least one if the flag is clear; a round of the fade's wait in `music_start` or `music_stop`, four. Source: `re/notes/headless.md`, "Scheduling", the table; `tools/headless.py` (`SPINS`, `FRAME_UPDATE`, `_pass_begin`, `MUSIC_SPINS`, `MUSIC_SPIN_VBLANKS = 4`); `tools/headless_os.py`, `os_graphics_WaitTOF`, `os_dos_Delay`; review B6.
34a. In flight the program waits in the spin of `wait_vblank`, which `frame_update` calls first; in the front end most of the waiting is `WaitTOF` (sheet only). Source: `SPEC.md` 3.3 ("`frame_update` begins with `wait_vblank`"); `re/notes/frontend.md`; review B8.
34b. How the pass's start and the spin differ: the pass's start is the one wait point at which the program does not say how many VBlanks it wants; the run's setting says it, and there the harness delivers the VBlanks the setting still owes since the last pass began, at least one if the flag is clear, so the spin the pass calls first finds the flag set and falls through. The spin delivers a VBlank of its own only where the program reaches it with the flag clear, where the front end waits to show a picture (`wait_vblank`'s other callers, `view_show_wait` and `cop_show_wait`). `wait_next_vblank` clears the flag before it spins and so always gets a VBlank of its own (its callers `main` and `run_queued_ticks`). Source: `tools/headless.py`, `_pass_begin` (`owed = max(self.vblanks_per_pass - self.since_pass, 0)`, and one if that is 0 and the flag is clear), `_spin`, `_drive`; `re/Wings.lst` `0x01AA32`–`0x01AA4E` and the headers' callers; `re/notes/headless.md`, "Scheduling", the table; review C1, B20.

The spin's label is `loc_01aa44`. Source: `re/Wings.lst` `0x01AA3E`–`0x01AA4E`; `re/functions.csv` (`01aa3e`, asm); `SPEC.md` 3.3, "Passes are not pure rendering" ("`frame_update` begins with `wait_vblank` (`0x01AA3E`)").

## Wall time never shapes a run

85. 86. Source: `re/notes/headless.md`, "Unicorn, as it behaves here", fifth point; `tools/headless.py`, `_drive`, docstring.
87. The cure: slices ended by the instruction counter; the wall clock only ever ends a run, as Stuck: when the program reaches none of the places the harness stops it at, no wait and no library call, for 60 s ("a minute"; in `_drive` the clock is reset after every stop the driver handles: a library call, a call into a loaded segment, a spin, and every other stop of `self.stops`, a pass's start and end and a tick's among them), or when a whole run takes longer than 1,800 s ("half an hour"). The notes say "no wait point", which is narrower than the code. Source: `tools/headless.py`, `STUCK_SECONDS = 60.0`, `WALL_LIMIT = 1800.0`, `Stuck`, `_drive` (`waited = time.time()` after a handled stop); `re/notes/headless.md`, "Unicorn, as it behaves here", fifth point; `re/notes/testing.md`, "The wall-clock limits of the headless original"; review B19.
94. Why those limits: measured under the suite's parallel phase, the longest stretch between two wait points was about 8 s with the machine idle and about 10 s with 6 workers and the owner at the machine, the longest whole run 327 s idle and 701 s busy; the limits were 10 s and 600 s, and with 12 workers a recording reached 600 s and its two tests failed as Stuck; so the limits are sized for a loaded machine. The prose's table: "about 10 s" against 60 s, "about 12 minutes" (701 s) against "30 minutes" (1,800 s), under the header "Longest measured, the suite running in parallel"; "tighter ones once failed tests on a busy machine though nothing was wrong". Source: `re/notes/testing.md`, "The wall-clock limits of the headless original", the table and the paragraph after it; `tools/headless.py`, the comments at `STUCK_SECONDS`, `WALL_LIMIT`.
95. The test `test_where_a_slice_ends_changes_nothing`: three flights with every kind of hook in use, in slices of 97 instructions (an odd length, so that the ends fall everywhere, inside a block with a hooked instruction too: the prose's words, from the docstring), of the default length and of 10^10 (one slice from each wait point to the next; the lengths sheet only, the prose says "the shortest" and "the longest" and the listing shows them), give the same records, the same random reads, the same schedule and the same observed calls; the short slices end more than 10,000 times, the longest never. Source: `tests/test_headless.py`, the test and its docstring; review C8.
96. The test `test_wall_time_only_ever_ends_a_run_as_stuck`: with the limit at nothing, the first slice that ends without a wait point makes the run Stuck. Source: `tests/test_headless.py`, the test.
97. With the counter every code hook fires once per execution of its instruction, so an observer keeps every call it sees; a guard against a hook firing twice is gone. Source: `re/notes/headless.md`, "Unicorn, as it behaves here", fifth point and the paragraph after the sub-points. (Sheet only, or one clause.)
98. The counter costs nothing measurable: the same mission recorded in 38 s with it and in 40 s with the timeout it replaced. Source: `re/notes/headless.md`, "Speed".

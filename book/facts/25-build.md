## 4. The build

30. **Build (of the page)** (term, defined here): `tools/build.py`'s making of `dist/wof.html` from the sources, the disk's files and the ROM, in four steps, with the native library as a second target. Source: `tools/build.py` docstring; `SPEC.md` 5.
31. The commands: `.venv/bin/python tools/build.py`, with `--native` also the native library, with `--debug` the core's debug information kept, `--quiet` without output. Source: `tools/build.py` docstring and `main`; `CLAUDE.md`, "Commands"; `README.md`, "Build".
32. Step 1, the tables: `tools/extract_tables.py` reads the manifest `re/tables.toml`, 122 entries, and writes `src/gen/tables.c` and `src/gen/tables.h` from the bytes of `Wings` and `original/kick.rom`, the byte order converted; `src/gen/` is not versioned and is made again at every build; hand-written sources hold code only. Source: `SPEC.md` 5, step 1; `tools/extract_tables.py` docstring; `tools/build.py`, `extract_tables`; counts table (122). Chapter 3 told the manifest and its reason; the chapter links it.
33. Step 2, the files: the 55 game files of the disk, all but `Wings`, `UFXintro`, `wingt`, every `.info` file and every dotfile, are packed into one blob: the magic `WOFS`, a version, the count, the directory's offset, then 40-byte entries of a 32-byte name, an offset and a length, big-endian; the files stay in their original formats. Source: `SPEC.md` 5, step 2; `tools/build.py`, `SKIP_NAMES`, `game_files`, `pack_fs`; counts table (55; `pack_fs` reports 543,240 bytes packed, sheet only). Chapter 3's sidebar told the layout; a clause.
34. Why one blob: a page opened from a file can load no second file, so everything travels inside the page. Source: `tools/build.py` docstring ("nothing is fetched, imported or streamed, because none of those work from a file URL"); chapter 23, "A small program that knows no game".
35. Step 3, the core: `src/*.c` and `src/gen/*.c` compiled with `python -m ziglang cc -target wasm32-freestanding` into `dist/core.wasm`, with `-std=c11 -O2 -Wall -Wextra -nostdlib -Wl,--no-entry`, the source paths mapped to `.` and `-g0`; the exports by the `export_name` attribute. Source: `tools/build.py`, `CC_WASM`, `sources`, `compile_wasm`; `src/wof.h` line 14 (`WOF_API`, `export_name`); `SPEC.md` 2 (the minimal line) and 5, step 3. Freestanding glossed by chapter 22's term, linked.
36. Listing 2: `CC_WASM` of `tools/build.py` with the comment above it: `-g0`, because zig cc writes DWARF by default, which more than triples the core, and the page alone is the release; `--debug` keeps it, for stepping through the core in a browser's developer tools; the prefix map makes the source paths relative, so that a debug page names no directory of the machine that built it either. Source: `tools/build.py` lines 46-53.
37. Step 4, the page: `web/index.html` is the template; the build inlines `web/style.css`, the seven modules concatenated in dependency order into one scope with their whole-line imports and leading `export` keywords stripped, the audio worklet as a string, and the base64 of `core.wasm` and of the blob; it fails if any module syntax is left, an imported name is not defined, a placeholder is not filled, or the page is over 2 MB (2,097,152 bytes). Source: `tools/build.py`, `MODULES`, `bundle_js`, `inline_worklet`, `assemble`, `SIZE_LIMIT`; `SPEC.md` 5, step 4. Chapter 23 told the joining; the chapter says what fails.
38. The build prints one line per step: the tables (the keymap's and the font's source in the ROM, the entries written), `files` with the count and the bytes packed, `core` with its bytes, `native` with its bytes (with `--native`), `page` with its bytes and MiB.
